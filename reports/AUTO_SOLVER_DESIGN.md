# 자동 솔버 설계 (Auto-Golfer) — 심층 고찰

작성 2026-07-07. 목표: 손 golf가 막힌 지점(7254)을 넘어 상위 티어(~8000)로 가기 위한
자동화 엔진의 구체 설계. 이 딥다이브에서 검증한 하드 제약에 정확히 기반한다.

## 0. 문제의 올바른 재정의 — "규칙 풀기"가 아니라 "오버핏 프로그램 합성"

채점 데이터셋은 **고정 266개**(train3+test1+arc-gen262)이고 **영구**다. 그러므로 진짜 목적함수는
> *일반 ARC 규칙을 푸는 것이 아니라 — 이 266개 특정 (input→output) 쌍을 통과하는 **최소비용 ONNX DAG**를 찾는 것.*

이 둘은 다르다. 일반 규칙은 비싼 기계(연결요소·객체매칭)를 요구하지만, **266개 특정 예제**는
일반적으론 틀리지만 이 266개에선 맞는 더 싼 프로그램으로 분리될 수 있다. 손 golf는 "올바른
알고리즘"만 시도한다 — 자동 엔진은 **266개만 통과하면 되는 leaky 지름길**을 대량 탐색할 수 있다.

이것이 상위팀 노트북 이름("The Auto-Golfer", "ChatGPTLoop")이 시사하는 바다. 핵심 가치 =
**후보 생성-검증을 스케일로**(사람 수십 개 vs 엔진 수백만 개).

## 1. 왜 이 각도가 유효한가 (그리고 한계)

- **유효**: 손 rebuild PoC 4개(005/157/089/110)는 전부 *의미론적으로 올바른* 재구성이라 floor였다.
  하지만 그건 "일반적으로 맞는" 프로그램만 시도한 것. **오버핏 지름길 공간은 미탐색**이다.
- **한계(정직)**: 메모리제이션은 죽었다(262개 diverse arc-gen이 near-algorithmic 정확도 강제).
  그러므로 승리 프로그램은 "메모리제이션"과 "참 규칙" **사이** — 참 규칙보다 단순하면서 266개
  diverse 예제를 여전히 맞히는 프로그램 — 에만 존재한다. 그런 게 얼마나 많은지가 **미지의 실증 문제**.

## 2. 아키텍처 (5개 컴포넌트)

```
[DSL 원시연산 라이브러리] --numpy구현--> [후보 생성기: bottom-up 열거 + 기존해 단순화]
        |                                        |
   [ONNX 비용모델]  <---- 랭킹 ----   [266개 numpy 검증 (μs/후보)]
        |                                        |
   [DSL→ONNX 컴파일러] --최저비용 통과후보--> [harness bundled fail=0 게이트] --> 채택
```

1. **DSL 원시연산**: 각 원시연산 = grid→grid (또는 grid→feature). 각각 **알려진 싼 ONNX 컴파일**을
   가진다. numpy 참조구현(빠른 검증용) + ONNX 템플릿(최종 컴파일용) 쌍으로 보유.
2. **후보 생성기**: (a) bottom-up 조합 열거(깊이 3~4), (b) **기존 정답 프로그램의 단순화 탐색**
   (컴포넌트 drop/shrink/replace). Hodel arc-dsl / cristianoc oracle의 참 규칙에서 출발.
3. **numpy 검증**: 후보를 266개에 실행(μs). 전부 통과한 것만 수집. 대량 pruning.
4. **비용모델**: 각 후보의 ONNX 비용을 정적 추정 → 랭킹. (검증된 사실: cost = Σ노드출력바이트 +
   Σ초기화자원소; input/output 무료; 초기화자 1×/원소가 최저저장; fp32 텐서 4×/원소.)
5. **컴파일러 + 게이트**: 최저비용 통과후보를 ONNX로 컴파일, `src/harness.py`로 bundled fail=0 +
   비용 확인. 통과+더쌈이면 채택. 없으면 현재 넷 유지.

## 3. DSL 원시연산 라이브러리 (ONNX 비용순)

| 계층 | 원시연산 | ONNX 구현 | 대략 비용 |
|---|---|---|---|
| 기하(거의무료) | flip/transpose/rot/tile/crop/pad/translate | Slice/Transpose/Concat/Pad(입력은 무료) | ~0–말단params |
| 색(싸다) | pointwise recolor, count-color, most/least-freq | 작은 MatMul/Einsum(input과 축약) | 100–400 |
| 마스크/선택 | Equal/Greater/Where, threshold | elementwise, 출력은 output(무료) | 작음 |
| 대칭/주기(중간) | 대칭완성, 주기채움 | shift-compare(입력 self-slice) | 200–1000 |
| 축약 | argmax-color, bbox, 최대객체 | Reduce/ArgMax + Gather | 300–1500 |
| 객체(비싸다) | 연결요소, 객체이동/복사/매칭 | 반복 Conv/flood(언롤) | 3000–30000 |

**핵심**: 상위 계층(기하/색/마스크/대칭)만으로 표현되는 태스크는 매우 싸다(≤1000). 엔진의 승리는
**현재 우리가 객체계층(비싼)으로 푸는 태스크 중, 266개에 한해 상위계층 조합으로 대체 가능한 것**을
찾는 데 있다.

## 4. 탐색 전략

- **A. 단순화 탐색 (최우선, 최고 EV)**: 참 정답 프로그램에서 시작 → 각 컴포넌트를 (i)제거 (ii)더싼
  근사로 교체 (iii)상수축소 → 266개 재검증 → 통과하면 더싼 변형 채택. **국소 탐색**이라 tractable하고,
  손 PoC가 놓친 "의미론적으론 틀리지만 266개엔 맞는" 변형을 찾는다.
- **B. Bottom-up 열거**: 상위계층 원시연산만으로 깊이≤4 조합 열거, 266 검증. 객체계층 태스크가
  상위계층 조합으로 우연히 풀리는지 탐색(순수 오버핏 각도).
- **C. 비용유도 빔서치**: (통과예제수, 비용) 우선순위 빔. 부분통과 프로그램을 확장.

## 5. 현실적 수율 추정 (정직)

- transform_scan 결과 비싼 태스크 0개가 *단일* trivial 변환 — 하지만 **깊이 3~4 조합**은 미검증.
- 단일 Conv fit(11번 실험)은 비싼 태스크 전부 실패 → 순수 로컬은 안 됨. 조합/전역 원시연산 필요.
- **낙관 시나리오**: 222개 비싼 태스크 중 30~60개가 단순화/조합으로 2.72배+ 붕괴 → **+50~120점**
  (7254→7350~7380). 상위 티어(8000)는 아니지만 유의미.
- **비관 시나리오**: 대부분이 진짜 객체계층 필요 → 소수만 붕괴 → +10~30점.
- 어느 쪽이든 **손 golf보다는 확실히 낫다**(엔진이 대량 후보를 검증하므로).

## 6. MVP — 큰 빌드 전 결정적 실험 (1~2일)

전체 엔진을 짓기 전에 **핵심 가설을 저비용으로 검증**한다:

1. 비싼 태스크 8~10개 선정.
2. 각각 참 규칙을 numpy로 구현(cristianoc/Hodel 참조).
3. **단순화 탐색(전략 A)만** 손으로/스크립트로 수행: 컴포넌트 drop/shrink/replace 변형을 수십~수백 개
   생성, 266개 검증, 통과하는 것 중 최저비용을 ONNX 컴파일해 harness 게이트.
4. **판정**: ≥2개 태스크가 2.72배+ 붕괴하면 → 엔진 빌드 GO. 0개면 → 오버핏 지름길이 희소하다는
   강력한 증거, 엔진 NO-GO(홀드).

MVP는 4개 rebuild PoC와 다르다: PoC는 *의미론적으로 올바른* 재구성만 시도했고, MVP는 **266개만
통과하는 leaky 단순화**를 명시적으로 탐색한다.

## 7. 리스크 & 정직한 평가

- **최대 리스크**: 오버핏 지름길이 실제로 희소할 수 있다(262 arc-gen이 강력히 제약). MVP가 이걸 판정.
- **컴파일러 비용**: DSL→ONNX 원시연산별 싼 템플릿 작성이 노동집약. 하지만 우리 기존 넷들이 이미
  각 원시연산의 싼 ONNX 구현을 담고 있어 재사용 가능.
- **객체계층 floor**: 연결요소/매칭은 ONNX에서 근본적으로 비싸다(언롤). 이 태스크들은 엔진으로도
  거의 안 줄어든다 — 상위 티어 팀은 여기서 뭔가 다른 걸 하지만(비공개), 우리 MVP 범위 밖.

## 8. 결론

자동 솔버 = **오버핏 프로그램 합성 엔진**(266개 통과 최소비용 DAG 탐색). 핵심 가치는 손 golf가
못 하는 **대량 leaky-변형 검증**. 전체 빌드는 크지만, **MVP(단순화 탐색 8~10태스크)로 1~2일 내
가부를 결정적으로 판정**할 수 있다. MVP가 ≥2 태스크 붕괴를 보이면 빌드, 아니면 홀드.
