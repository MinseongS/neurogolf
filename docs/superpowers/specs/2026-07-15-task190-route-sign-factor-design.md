# Task190 Route Sign Factor Design

## Objective

Reduce task190 from cost1367 to at most1237 without changing its coordinate recovery or
FREE-output polynomial renderer, then continue every byte-proven compatible fold. The dense
`poly_route[2,10,10]` route, dynamic colour branch, duplicate quadratic core, and repeated ray
features were all collapsed. Final achieved endpoint: **cost1127, bundled266/266**.

## Chosen representation

The current output is algebraically `color + P*(input-color)`, where
`P=(w-diag)^2(w-anti)^2`. On ray cells `P=0`; on every other integer column `P>=1`.
The only input colours reachable for paint colour `c` are background `s=0` and `s=c`.

Exact identity routing is unnecessary. Use

`A(k,s) = 1 - (k-s)^2`.

For `k=s`, A is1. For every wrong channel A is non-positive. Keeping the colour branch's route
equal to1 gives `color_k + P*(A(k,s)-color_k)`. At P=0 only the paint colour is positive. At
P>=1, the active input channel stays positive; every wrong channel is non-positive, including
the paint channel on background cells. Values are integer-exact in fp32 over colour indices0..9.

Factor A with shared features `F[x]=[1,x,x^2]`:

`route[v,k,s] = sum_IJ F[k,I] * F[s,J] * C[v,I,J]`.

For v=0, C encodes `1-k^2+2ks-s^2`; for v=1, only `C[1,0,0]=1`.
`F[10,3]` and `C[2,3,3]` cost48 parameters, replacing200 and predicting
memory750 + params465 = cost1215, `ln(1367/1215)=+0.1175`.

## Rejected alternatives

- Pow feature expansion: a single product-form Einsum cannot omit dynamic d/a operands on
  individual monomials without recreating a `[1,x]` feature carrier. A 16-term coefficient alone
  is insufficient.
- Exact route CP: identity rank10 plus the all-ones branch needs rank11 and about242 parameters.
- Full mask/label reconstruction: counted 10x10 masks and colour-index carriers exceed the saved
  route bytes before output decoding.

## Runtime and correctness gates

The terminal Einsum grows from17 to19 operands. Before a full gate, evaluate one official example
in a fresh process with a 10-second hard timeout and require elapsed<2 seconds. Exhaustively verify
all paint colours1..9, reachable input colours `{0,c}`, output channels0..9, and every actual P
value generated by w,d,a in0..16. Then require bundled fail0, cost<=1215, and `ng gate` PASS before
`ng adopt`.

## Post-adoption colour-branch fold

After the cost1215 route factor lands, replace the exact dynamic one-hot colour branch as well.
Use `A(k,s)=0.5-(k-s)^2` for input routing and
`B(k,c)=(1/128)*(0.5-(k-c)^2)` for paint routing. The final score is
`B + P*(A-B)`.

- If input colour equals paint colour, A and B have the same sign, so scaling cannot change the
  winner.
- On background, epsilon1/128 makes B no more negative than A for every wrong channel0..9; hence
  increasing P cannot cross positive. The paint channel is driven non-positive for P>=1.
- On rays P=0, B is positive only at the paint channel.

Obtain dynamic `[1,c,c^2]` by `ArgMax(color_vec)` followed by `Gather(F)`, reusing the existing
30-parameter F. Replace `poly_color_branch` and `poly_color_ones` with `color_core[2,3,3]`.
Expected memory is `750-80+8+12=690`, params `465-10+18=473`, cost1163.

## Symmetric ray-polynomial fold

The four factors `(w-d)(w-d)(w-a)(w-a)` equal
`(w^2-(d+a)w+da)^2`. Cap out-of-grid roots at10 rather than16; both are outside output columns0..9,
and the smaller cap makes `d+a<=20`, `da<=100` exact in uint8. Build one dynamic feature
`[1,d+a,da]` and one constant spatial feature `[support,w,w^2]`, then use a `[t,3,3]` core twice.
This deletes two fp32 Casts and two `[10,2]` Pow carriers. Expected memory690->620 and params459->507,
so cost1149->1127 while reducing the terminal operand count by six.
